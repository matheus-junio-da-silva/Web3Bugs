## Declaração CVL original no intervalo catalogado
```cvl
rule token_totalSupply_independence(method f)
filtered {
    f -> f.selector != safeBatchTransferFrom(address,address,uint256[],uint256[],bytes).selector
}
{
    uint256 token1; uint256 token2;
    require token1 != token2;

    uint256 token1_before = totalSupply(token1);
    uint256 token2_before = totalSupply(token2);

    env e; calldataarg args;
    require e.msg.sender != owner(); // owner can call mintBatch and burnBatch in our harness
    f(e, args);

    uint256 token1_after = totalSupply(token1);
    uint256 token2_after = totalSupply(token2);

    assert token1_after != token1_before => token2_after == token2_before,
        "methods must not change the total supply of more than one token";
}
```

## Assertion, calls e falsificação
A condição afirmada é `token1_after != token1_before => token2_after == token2_before, "methods must not change the total supply of more than one token"`. Um contraexemplo exigiria uma execução permitida pelas pré-condições e summaries em que pelo menos uma dessas expressões seja falsa.
- Predicado registrado na matriz original: `token1_after != token1_before => token2_after == token2_before,`.
- Calls registradas: `safeBatchTransferFrom; totalSupply; owner; f`. Verificar sequência, os `lastReverted`, `require` e `assert` locais antes de alterar a estrutura.
