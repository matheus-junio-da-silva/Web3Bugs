## Literal rule/invariant and falsification
```cvl
rule withdraw(uint256 index) {
	env e;
	uint256 _balance = sinvoke ercBalanceOf(e.msg.sender);
	uint256 val = sinvoke getPendingWithdrawalsIndex(e.msg.sender, index);
	sinvoke withdraw(e, index);
	require (e.msg.sender != currentContract);
	uint256 balance_ = sinvoke ercBalanceOf(e.msg.sender);
	assert(
    _balance + val == balance_,
    "Withdraw balance not updated"
  );
}

```
- Key predicate/asserter lines: "require (e.msg.sender != currentContract);"; "assert("; "_balance + val == balance_,".
- Falsification requires admissible require/method filter and false assert or invariant under relevant state; not automatically a reachable target action. Original catalog detection intent: Withdrawing a pending amount must increase the receiver's balance by that entry's value; the rule is also a prover-model diagnostic..
