## Literal assertion and counterexample
The literal rule at contracts/21/specs/DSM.spec:11-35 declares unconstrained env e, depositRoot, keysOpIndex, blockNumber, blockHash and three DSMH.Signature values. It reads getGuardianQuorum() into a local quorum variable but NEVER uses that value. It calls depositBufferedEtherHarness@withrevert and asserts !lastReverted. Therefore the actual check demands that an arbitrary symbolic deposit SUCCEED, including potentially invalid inputs. It does not check that invalid deposits revert.

A counterexample to this proposed guarantee is any reverted harness call, subject to whatever an authentic harness implements. The real DepositSecurityModule.depositBufferedEther explicitly reverts with DepositNoQuorum if quorum is zero or signatures are insufficient (Solidity:419), and may revert for wrong deposit root (422), inactive module (424), frequency (427), block hash (428), nonce (431) or signature (454-455). A fresh contract with quorum=0 is an expected revert scenario. This is a source-level illustration, NOT a replayed Prover counterexample for the missing harness.
