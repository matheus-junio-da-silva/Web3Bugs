## Motivation

Detect a zero-value slash or returnFunds changing the exchange rate **on executable, nonreverting paths**. The latest supplied implementation instead rejects these calls, so the proof's interpretation is limited by reachability.

## Reconstructed methodology

The following is reconstructed from the observable CVL property, available Solidity/harness code, and report. It is not a claim about private auditor reasoning.

1. Snapshot the exchange rate and initial storage.
2. Invoke `slash(destination, 0)` and observe the exchange rate if the call completes.
3. Separately invoke `returnFunds(0)` at `initialStorage` and observe its exchange rate if the execution reaches that point.
4. Assert both observed rates equal each other and the original rate.

A counterexample requires executable paths through the calls and a changed exchange rate. A revert before the assertions does **not** furnish evidence that a successful zero-value call left the state unchanged. In the supplied Solidity, `slash(0)` reverts at `require(amount > 0, 'ZERO_AMOUNT')` and `returnFunds(0)` would fail its LOWER_BOUND check; this is compatible with the report's latest ✔, but is not a successful-operation no-op proof.

## Why the Solidity excerpt is relevant

The excerpt shows the `require(amount > 0, 'ZERO_AMOUNT')` guard in `slash` and `require(amount >= LOWER_BOUND, 'AMOUNT_LT_MINIMUM')` in `returnFunds` (StakedTokenV3.sol:271-308). On paths that pass those guards, the methods derive/store a rate through `_getExchangeRate` and `_updateExchangeRate`; on zero-amount paths in the supplied version, execution reverts before this update. The historic property and reported historical counterexample predate those guards.
