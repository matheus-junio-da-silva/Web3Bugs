## Motivation

Check directional withdrawal accounting without overstating it as an exact-amount proof.

## Reconstructed methodology

The following is reconstructed from the observable CVL, available Solidity, report, and recovered public verification metadata; it does not claim access to private auditor reasoning.

1. Snapshot recipient underlying, aToken, and reward balances. 2. Execute the harness withdrawal path with symbolic token choice. 3. Compare the post-state using the rule's nondecrease/equality conditions.

A counterexample satisfying the rule/invariant preconditions would be: If toUnderlyingAsset is true, the recipient's underlying balance decreases or its aToken balance changes; if false, the aToken balance decreases or the underlying balance changes; or the reward balance decreases.

## Why the Solidity excerpt is relevant

Bridge.withdraw computes the dynamic amount from staticAmount, chooses lendingPool.withdraw for underlying payout or aToken.safeTransfer for aToken payout, and then may transfer rewards. Those branches correspond directly to the three balances read by the rule. The rule itself calls the missing BridgeHarness.initiateWithdraw_L2 helper, so the excerpt is implementation context rather than the exact verified entrypoint.
